With these, the site owner picks from your site's real categories and authors in the RankHouse editor, instead of typing names. The names they pick arrive in the `categories` and `author` fields of [new posts](/endpoints/create-post).

Each one has its own capability, so you can build one without the other.

## Categories

```http
GET {base_url}/blog-categories?per_page=100&page=1
```

Capability: `blog_categories`. Answer with a JSON array (or an object with the array in `items`):

<ResponseField name="id" type="string" required>
  Your id for the category.
</ResponseField>

<ResponseField name="name" type="string" required>
  The name shown in the editor and sent back in posts.
</ResponseField>

<ResponseField name="slug" type="string">
  The category's URL slug.
</ResponseField>

```json
[
  { "id": "1", "name": "News", "slug": "news" },
  { "id": "2", "name": "Guides", "slug": "guides" }
]
```

### Add a category

```http
POST {base_url}/blog-categories
```

Also capability `blog_categories`, so build it together with the list. RankHouse calls it when the site owner adds a category your site doesn't have yet: with **Add as a new category** in the editor's category picker, by accepting a suggested category, or through an AI assistant connected to RankHouse.

<ParamField body="name" type="string" required>
  The new category's name.
</ParamField>

<ParamField body="description" type="string" required>
  Always `""` for now.
</ParamField>

<ParamField body="slug" type="string" required>
  Always `""` for now. Make the slug from the name yourself.
</ParamField>

<ParamField body="parent" type="number" required>
  Always `0` (no parent).
</ParamField>

```json Example request
{ "name": "Trail running", "description": "", "slug": "", "parent": 0 }
```

Answer with any `2xx` status and the category as you saved it, with the same fields as the list: `id`, `name` and `slug`. RankHouse files posts under the `name` you send back.

```json
{ "id": "3", "name": "Trail running", "slug": "trail-running" }
```

If you already have a category with that name (in any letter case), answer with that one instead of making a second copy. If you can't add it, answer with a `4xx` status and `{ "error": "..." }`. The site owner sees your message.

## Authors

```http
GET {base_url}/authors?per_page=100&page=1
```

Capability: `authors`. Answer with a JSON array (or an object with the array in `items`):

<ResponseField name="id" type="string" required>
  Your id for the author.
</ResponseField>

<ResponseField name="display_name" type="string" required>
  The name shown in the editor and sent back in posts. If you only have `name`, send that instead.
</ResponseField>

```json
[
  { "id": "7", "display_name": "Jane Doe" },
  { "id": "9", "display_name": "Sam Lee" }
]
```

## Notes

- The editor reads the first page, up to 100 of each.
- Posts carry **names**, not ids. Match them to your categories and authors by name when you save the post.
- No user system? A short fixed list of author names is enough.
